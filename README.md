# ExoEQ — Feature Spec & Production Plan

Oct 14, 2026 · tracked by @Tachy Bunker

## Vision & target formats

ExoEQ is a node-based filter/EQ instrument-grade effect: a chain of filter "nodes", each running Airwindows-derived and custom filter types (including a continuous Z-morph LP-BP-HP filter), with per-node sends, sidechain, MTS-ESP/SCL-TUN tuning, and a generative layer for building whole filter series from a formula, an image, or a sample's spectrum.

Ship target: VST3, AAX, and CLAP, for Windows and macOS. Release plan: priced at $25/unit, given away free sometimes for testing, with an encrypted license check verified server-side via the Exomusica website.

Built on iPlug2 (a thin C++ wrapper over the native VST3 SDK, chosen for maximum compiled performance without hand-rolling plugin-lifecycle plumbing). iPlug2 natively supports VST3, AAX, and CLAP from one codebase — see Open risks for the AAX-specific access/signing requirement, which is separate from the build toolchain.

## Feature inventory

Everything proposed so far, grouped by subsystem, kept exhaustive on purpose so nothing drops across sessions.

**Core engine**

- Airwindows-derived filters as selectable types, including self-oscillating and exotic variants (Icarus-3-style); hard and soft downsampling as filter types; a continuous Z-morph filter (LP↔BP↔HP).
- Reorderable per-node series ("order of effect"), each node with a Delta (solo-the-band) switch.
- Node groups: a node can belong to multiple groups at once; group parameters are accumulative (bitmask: grp 1, 2, 4…); a global "anything" envelope auto-disables once ≥1 group exists, re-addable manually.
- Per-node contained functions: sidechain input, sends (frequency shifting, distortion, delay), with the option to mute or Delta the original band.
- Everything-to-everything modulation: any parameter assignable to any destination, including self-referential routing (e.g. sidechain cutoff modulated by itself); full macro control; math functions on any connection.
- Performance-first by design: minimal GUI animation load; feature-pack toggles to disable unused modules (deliberately deferred — premature optimization per mrugalla).

**Tuning & pitch**

- MIDI + MTS-ESP keytracking per band, with math (×, +/-) on every band; latch; portamento.
- SCL & TUN import, with an "un-MTS" option.
- Optional pitch tracking.
- Base frequency settable as Hz, 12edo note name, or "current note input."

**Generative / transform layer**

- Band-series generator function, including fractal-formula support (frequency as the fractal parameter for new series nodes).
- Transform filter: takes a line/function (e.g. a harmonic distribution) and reshapes it into a new timbre spec — inharmonic-capable, morphable between multiple targets.
- Global node-frequency stretch with a specifiable center point ("timbre elasticity" — stretches timbre without moving the root note, via root-tracked frequency shifting).
- Image resynthesis as a spectral filter: image luminance per line read as an EQ curve (the Serum-wavetable analogy), FFT-based.
- Sample/spectral-response capture as a playable "instrument" (record a sound, the plugin extracts its spectral response as a playing surface) — flagged as hard but high-potential.
- Long-shot: train a model to resynthesize/EQ-match through the custom filter set automatically (Synplant-2-style).

**FFT-domain layer**

- FFT bandpass "containers": stretch partials, frequency-shift within them.
- Continuous morph knob between phase modes, settable globally or per group.
- "Natural EQ" mode: bells/shelves auto-paired with a small opposing bell; the outermost compensator gain-reduces once boosts stack too far into the highs (mirrored in the lows).

**Adjacent / spinoff plugins** (not part of ExoEQ, same brainstorm)

- Standalone inharmonic saturator: user controls how added harmonics behave.
- Synth mode bolted onto the EQ concept: self-oscillating filter as oscillator, triggered/looping sample or additive engine with basic waves + stretch.

**UX / product notes**

- Use-case taxonomy to steer design: split features into "useful for normal people" (defaults, discoverability, presets) vs. "extreme sound design" (deep patchability) before UI design goes deep.
- Ring-mod/audio-rate-mod visual feedback should use a decoupled jitter animation, not a literal audio-rate redraw (GPU/CPU cost).
- Licensing: priced at $25 per unit; given away free sometimes for testing; needs encrypted authentication verified server-side via the Exomusica website.

## Architecture decisions

- Filter interface (`IFilterNode`): the concrete filter type is chosen at block-process time, never per-sample, keeping virtual dispatch out of the hot loop.
- Reference filter: a zero-delay-feedback state-variable filter (TPT/Cytomic design) that outputs LP, BP, and HP simultaneously, so Z-morph is a crossfade between those outputs rather than a switch between filter objects; self-oscillation falls out naturally at high resonance.
- Keytracking is isolated behind one function (MIDI-note-to-Hz today); MTS-ESP/SCL-TUN retuning replaces it later without touching callers.
- Signal topology: bands run in parallel internally (not series), summed with per-band gain/Delta — mrugalla's parallel-bandpass-vs-series-bells tradeoff from Hammer & Meißel, chosen because it avoids the gain-compensation "floor" problem and keeps per-band sends/sidechain isolated. "Order of effect" governs intra-band effect chains, not global signal flow.
- Modulation matrix: one generic system handling math functions and self-referential routing (e.g. sidechain cutoff modulated by itself), with cycle-safety designed in from the start rather than patched on per-feature.
- Generative layer: one generic "node-series generator" (a function mapping a parameter domain onto node placements) serves the fractal generator, the transform filter, and the image-to-EQ-curve feature as three input functions to the same machine, rather than three separate systems.
- FFT-domain features (containers, spectral capture, ML resynthesis) stay an optional parallel path so the time-domain core remains latency-free and a future Lite build can ship without them.
- Toolchain: iPlug2 (a thin C++ wrapper over the native VST3 SDK; also covers AAX and CLAP), chosen over raw-SDK or JUCE for the best performance-per-effort tradeoff.
- Licensing/auth: pricing is $25/unit with occasional free copies for testing; needs an encrypted license check that phones home to a server-side endpoint on the Exomusica website (shared infrastructure with that project, not a separate backend).

## Production roadmap

P0 — prove the filter math as plain unit tests (impulse/sweep/noise through the SVF), no plugin shell, portable and testable in the cloud sandbox. P1 — one filter node loading as a real VST3 (cutoff, resonance, morph, keytrack-amount only); this is the end-to-end toolchain proof, resist adding anything else here. P2 — real MTS-ESP + SCL/TUN keytracking, latch, portamento, still single-node. P3 — the series/chain abstraction: reorderable nodes, Delta solo, per-node sends and sidechain, parallel-band topology under the hood. P4 — grouping (accumulative bitmask groups, the global envelope) plus the generic modulation matrix with cycle-safe self-referential routing. P5 — the generative layer: one node-series-generator function serving the fractal generator, the transform filter, and image-to-EQ-curve. P6 — FFT-domain extras (frequency-shifting containers, spectral-capture-as-instrument, the ML resynthesis long-shot), kept as an optional path so the core stays latency-free.

## Open risks & decisions

- AAX access is not just a toolchain setting: Avid requires a developer agreement and PACE code-signing before an AAX build will even run in Pro Tools. This needs starting (account/approval) well before AAX is actually needed, not discovered at the end.
- Z-morph: decided — only filter types that support a continuous morph output expose it; filters that don't support it keep a fixed/discrete type. `IFilterNode` grows an optional capability flag rather than a mandatory one.
- CLAP: no real architectural hold-up — iPlug2 supports CLAP natively from the same codebase. What's missing so far is mechanical: the CLAP SDK hasn't been fetched yet (iPlug2 ships `download-clap-sdks.sh` alongside the VST3 one already used) and `FORMATS` in CMakeLists needs `CLAP` added. Treat this as a to-do, not a risk.
- Lite vs. Full split: intentionally deferred until there's a solid, complete product to split — not an open risk right now, just not yet relevant.
- Licensing is now a real dependency between two projects: ExoEQ's server-side auth check needs the Exomusica website's backend to exist and be reachable. Track this against Exomusica's own build status, not ExoEQ's.
- Morph crossfade dip (found in Phase 0): fixed. Switched StateVariableFilter.h from a linear LP/BP/HP crossfade to equal-power (sin/cos) — re-tested flat across the full morph sweep at every resonance level, synced to the real project.
